# Fix: Android onboarding crash - Navigation destination not found

## Root Cause

When user completes onboarding and taps "Done", `onDone` callback calls `navController.navigate(Screen.Home.route)`. But at that moment, `isMainTab` is still `false` (because `currentDestination` is still Onboarding), so the NavHost only contains Onboarding + sub-routes. "home" route doesn't exist in the NavHost graph → crash.

```
java.lang.IllegalArgumentException: Navigation destination that matches request 
NavDeepLinkRequest{ uri=android-app://androidx.navigation/home } cannot be found 
in the navigation graph startDestination={route=onboarding}
```

## Fix

**File:** `Android/app/src/main/java/com/example/supplementtracker/presentation/navigation/AppNavigation.kt`

### Change 1: Add Home/MyStack/History routes to NavHost (line ~219)

Add `composable(Screen.Home.route)`, `composable(Screen.MyStack.route)`, `composable(Screen.History.route)` inside the NavHost block, before the Onboarding route. This ensures the "home" route exists when `onDone` navigates to it.

### Change 2: Simplify `onDone` callback (line ~224)

Remove `navController.navigate(Screen.Home.route)` from `onDone`. Just set the flag and refresh — the NavHost's `startDestination` will automatically navigate to Home when `hasCompletedOnboarding` becomes true.

```kotlin
onDone = {
    prefs.edit().putBoolean("hasCompletedOnboarding", true).apply()
    refreshOnboardingFlag()
}
```

## Verification

1. Build: `$env:ANDROID_HOME = "D:\SDK"; .\gradlew.bat assembleDebug --no-daemon`
2. Install on device, complete onboarding → should navigate to Home without crash
3. Swipe between tabs → should work
4. Kill app, reopen → should go directly to Home (not onboarding)
